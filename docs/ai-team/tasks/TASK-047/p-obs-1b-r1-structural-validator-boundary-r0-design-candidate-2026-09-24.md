## Source-backed baseline

The merged `task047_capture_source_transport_receipts.py` is the only canonical R0 parser. It owns the 64-KiB UTF-8 wire limit, duplicate-key rejection (including nested objects), JSON nonfinite rejection, closed schema, identifier/hash syntax, UTC microsecond parsing, canonical JSON/digest domains, `ParsedCaptureReceipt`, and `STRUCTURAL_VALID_ONLY`. `validate_source_transport_pair` revalidates caller-supplied parsed objects, checks the exact `_LINEAGE_FIELDS`, predecessor, sample count and freshness ordering. Its `MappingProxyType(record)` is sufficient for today's flat R0 records but is **shallow**: it must not be cited as nested immutability for future R1 pause/window arrays. R0 accepts JSON trailing whitespace through `json.loads`; an R1 parser must not silently change that R0 behavior.

The [bounded-attempt design](p-obs-1b-bounded-attempt-freshness-r0-design-2026-09-23.md) permits only a single attempt whose stop, readback and receipts complete before independently verified expiry. The [writer/completeness](p-obs-1b-terminal-writer-completeness-r0-design-candidate-2026-09-23.md) and [pause/acoustic](p-obs-1b-r1-pause-acoustic-producer-boundary-r0-design-candidate-2026-09-24.md) candidates deliberately leave their public state/nullability and producer proof matrices open. No generic validator may infer those missing facts from R0 counts or the legacy float-WAVE receipt.

## Proposed parser and chain separation

1. Keep the R0 wire parser and pair validator public behavior byte-for-byte stable. An eventual R1 terminal parser should be a separately named, additive entry point in the TASK-047 receipt package, not a second canonical R0 implementation. Shared private helpers are eligible only after a golden R0 parity corpus proves the same accepted bytes, rejected bytes, error codes, digest and `STRUCTURAL_VALID_ONLY` result. That corpus must include acceptance of raw `SP`, `TAB`, `CR` and `LF` after a complete JSON object, each counted inside the 64-KiB wire limit, plus rejection beyond the limit; these are distinct from line terminators inside field values. Do not replace the R0 schema mirror or reinterpret R0 freshness/transport states.
2. The eventual terminal parser must first enforce a closed wire envelope: strict UTF-8, no BOM, at most 64 KiB including whitespace, exactly one JSON object, duplicate-key rejection at every depth, no NaN/Infinity, no unknown fields, exact type/version/domain, strict integer tokens (not booleans or integral-looking floats), closed timestamps, exact digest exclusion and canonical preimage. A distinct terminal digest domain and predecessor relation require the accepted R1 ABI; the candidate domain in the gap map is not allocated here. Whether R1 accepts trailing JSON whitespace must be explicitly selected and tested; R0 remains unchanged.
3. The parsed terminal value must be deeply immutable or own a read-only canonical wire snapshot from which all checks are rerun. If using a recursive immutable tree, preserve JSON object versus array identity (`MappingProxyType` versus tuple), preserve `bool` versus `int`, and never expose mutable child dictionaries/lists. Reconstructing a mutable validation copy must be deterministic and must preserve exactly the originally parsed JSON types. A frozen dataclass around a mutable `fields` tree is insufficient.
4. An eventual three-record chain validator accepts only the exact parsed source V1, transport V2 and terminal R1 types. It must revalidate all three records and their wrapper metadata rather than trusting caller-created or `dataclasses.replace`-modified objects; invoke the canonical R0 pair check, then check terminal predecessor equals the exact transport digest, terminal repeated transport digest if allocated, equality only of R0 `_LINEAGE_FIELDS`, and the accepted bounded-attempt UTC/freshness order. R0 discriminator/version/digest/time fields are **not** lineage-equality fields. No public API should return `BOUND_VERIFIED`, `COMPLETE`, `ADMITTED`, or a custody/Asset/Job capability; the maximum parse/chain result is `STRUCTURAL_VALID_ONLY`.
5. Keep structural validation separate from producer attestation and stateful idempotency. The pure parser cannot authenticate a self-consistent digest, prove current Consent/source/Job/time, decide that a physical writer closed, detect duplicate terminal issuance across calls, or select a current durable Job head. Those require independently allocated producers, journal/CAS and native Evidence. A failure or partial terminal may still be structurally valid only if its **later frozen** R1 matrix explicitly permits it; structural validity is never success.

## Fail-closed review and fixture contract

Before implementation allocation, freeze a public-safe closed error vocabulary and precedence without input-value/path echo. Negative fixtures must include malformed UTF-8/BOM, duplicate keys at top and inside pause/acoustic records, trailing non-whitespace bytes, wire-size boundary including whitespace, NaN/Infinity, `true` or `1.0` in integer fields, bad timestamp precision/time ordering, unknown field, unsupported type/version, wrong domain/preimage/digest, nested mutation attempt and forged parsed wrapper. Cross-record fixtures must include swapped project/attempt/Consent/subject/time/Job hashes, wrong predecessor or repeated digest, transport before source, terminal after expiry/equality at expiry, and a self-consistent forged triple that remains unauthenticated. The unchanged R0 pair may structurally accept nonzero gap/duplicate/reorder/overrun counters; a counter contradiction is a future **triple** negative vector only when an independently frozen terminal state asserts `COMPLETE`, with its expected error and precedence fixed then. R1 pause, acoustic, writer, coverage, packetless-failure and raw-readback fixtures are **blocked** until their exact field/state/producer contracts are independently accepted; do not fill them with guessed zeroes or fields.

Review must compare the R0 golden corpus before and after any helper extraction, check both canonical and packaged schema mirrors where a new schema is eventually added, and verify that all error text is public-safe. Focused parser/unit tests cannot prove trusted-time `D`, finite `B/G`, physical stop, raw readback, custody or native capture. A separate DEV-4 implementation design, independent Critic/Tester and exact allowed-file/gate decision remain required before source/schema/test mutation.

## Open decisions and next dependency

This boundary can be accepted without choosing the trusted-time producer or a numeric stop budget because it defines **what the parser must not claim**, not the R1 semantics. It cannot complete an ABI. Next, the canonical owner must allocate `TrustedCaptureTimeBindingV1`; TASK-047 must obtain finite `B/G` and producer proof for pause, acoustic, accepted-to-written accounting, readback and packetless failure; then an exact R1 field/state/nullability/error matrix can be reviewed. Until those are bound, R1 implementation and native issuance remain ineligible.
