4. Main has no accepted OwnerSubject START amendment, trusted capture-time producer, TASK-043 capture-currentness producer, TASK-003 capture-Asset adoption/readback or full custody binding. Opaque hashes in a structurally valid record do not satisfy those dependencies. TASK-098 A5 remains blocked.

## Proposed R1 record and shape — not frozen

The candidate discriminator is `NativeCaptureTerminalReceiptV1`, `schema_version=1`. It would reuse R0 common envelope names, ID/hash syntax, UTC microsecond time syntax, digest exclusion/canonical JSON rule and 64-KiB wire limit. Its digest domain would be a distinct `TASK047_NATIVE_CAPTURE_TERMINAL_V1\0`; its `predecessor_receipt_sha256` would equal the exact preceding transport digest, repeated in `transport_receipt_sha256`. No cross-receipt comparison may rely on a self-reported digest alone. The final type/version/domain remain unallocated until the time/renewal blocker below is resolved; this table is a field inventory, **not** an exact schema or producer contract.

The candidate R1 field families requiring later schema decisions are:

| Family | Required fields / closed values | Constraint |
|---|---|---|
| Stop | `stop_cause`: `HUMAN_STOP`, `DURATION_LIMIT`, `DISK_FLOOR`, `SOURCE_DRIFT`, `OBS_PROCESS_EXIT`, `DEVICE_LOSS`, `TRANSPORT_FAILURE`, `WRITER_FAILURE`, `RECOVERY_UNKNOWN` | A cause is an observation, not success or admission. No free-form path/error text. |
| Times | `capture_started_at`, `capture_finished_at` | Exact UTC microseconds; start <= finish <= envelope `observed_at`; receipt creation cannot precede finish. |
| Pauses | `pause_ranges`: ordered bounded records with `paused_at`, `ended_at`, `end_cause` (`RESUME` or `STOP`), and source-frame offsets at both boundaries | Candidate intervals are nonempty and half-open in time; a final `STOP` range ends exactly at `capture_finished_at`, without a fictitious resume. Source-frame offset units, origin and transport comparison still require a producer decision. |
| Raw writer/readback | `terminal_write_state`: `CLOSED_READBACK_MATCH`, `INCOMPLETE`, `UNKNOWN`; opaque `raw_staged_object_ref`, revision/content digests, byte count and a readback binding | Writer/readback state is **orthogonal** to capture completeness. A transport failure may leave a properly closed, read-back partial raw object for recovery. No value here is custody, publication, complete capture or admission. Nullability and readback digest preimage are not frozen. |
| Acoustic observation | `measurement_point` (`PRE_FILTER` or `POST_FILTER`), observed/clip/nonfinite counts, Peak/RMS/session-max and `acoustic_observation_state` (`OBSERVED` or `UNKNOWN`) | Candidate wire numbers are bounded integers/finite float32 bit patterns, not JSON floats. The exact window, unknown/null matrix, count relationships, bit-pattern rules and TASK-048 threshold boundary still require producer evidence; no quality PASS can be inferred. |

`raw_staged_object_ref` would be an opaque bounded ASCII identifier, not a location or capability. A raw-content hash would cover exact raw bytes only; it would not be a custody receipt or Asset digest. The producer/readback record type, its preimage and its relationship to TASK-082 V2's `TASK047_RAW_CAPTURE_OUTPUT` are **unresolved**. This terminal candidate alone must not be used as a TASK-082 write-lease input. A future implementation should prefer a separately named canonical/package terminal schema with byte parity and a shared wire/digest validator, without changing R0 public parse behavior; exact module/API and deep-immutability choices need review.

## Pair/triple structural validation and failure matrix

- A future standalone parser must reject duplicate/unknown fields, unsupported type/version, bad UTF-8, BOM, non-finite JSON, non-whitespace bytes after the JSON value, over 64 KiB, booleans or integral-looking floats in integer fields, invalid timestamps, digest mismatch, invalid pause geometry and inconsistent null/state matrices. Whether trailing JSON whitespace is accepted must be frozen before implementation without silently changing R0's existing whitespace behavior. The latter two matrices are not yet frozen, so no parser implementation is eligible. Errors must be closed public-safe codes; input values and private identifiers must never be echoed.
- A future triple validator must revalidate all three parsed records, not trust caller-created objects. Equality is limited to R0's `_LINEAGE_FIELDS`: `project_id`, `recording_session_id`, `segment_attempt_id`, `operation_id`, `idempotency_key`, `owner_subject_binding_sha256`, `consent_evaluation_sha256`, `producer_code_sha256`, `runtime_sha256`, `trusted_time_binding_sha256`, `capture_job_id`, `capture_job_revision_sha256`, and `capture_job_predecessor_readback_sha256`. Discriminators, versions, receipt/predecessor digests and times must differ or be checked by their own rules. A source/transport/terminal freshness inequality is **not yet defined** because R0 has no long-capture renewal model.
- A future validator may return only `STRUCTURAL_VALID_ONLY` for a well-formed complete or incomplete terminal record. A complete self-report never becomes `BOUND_VERIFIED`. Unknown, incomplete, mismatched or stale records cannot be transformed into an admission token by any parser result.
- Future negative vectors must cover swapped attempt/project/Consent/subject/time/Job hashes, cross-role replay, pause-stop edges, path-like raw refs and malformed numerical encodings. A transport failure with a closed/read-back partial object is a **positive recovery** case but never a successful complete-capture or admission case. A fabricated self-consistent digest may be structurally valid and is explicitly unauthenticated. Duplicate-stop/idempotency enforcement is stateful producer responsibility, not something a pure parser can infer from one record.

## Open design decisions before implementation START

1. **High — long-capture time/currentness:** R0 pair validation requires `transport.created_at >= source.observed_at` and `transport.fresh_until <= source.fresh_until`, with each receipt observed before its own `fresh_until`. A session that runs past that source freshness cannot be represented by a terminal chained to a single starting R0 pair. Decide a versioned renewal/checkpoint model or a separately proven end-of-capture source/transport pair before fixing any R1 time order; test expiry-crossing and rollback. Do not extend R0 freshness by assertion or silently relax its parser.
2. **High — writer/completeness/readback:** freeze independent writer-close/readback and capture-completeness states; full stop-cause × transport-state × write-state × raw-field nullability. Specify readback record type, producer, preimage and cross-hash rules. A closed partial object after failure must remain representable without claiming completion. Freeze opaque raw-ref syntax and TASK-082 V2's `RAW_CAPTURE` / `TASK047_RAW_CAPTURE_OUTPUT` handoff; terminal alone grants no write lease.
3. **High — pause/acoustic producer facts:** freeze source-frame offset origin, integer bounds, half-open ranges, stop-while-paused handling, measurement window, UNKNOWN/null matrix, sample-count relationships, finite float bit rules and clip policy ownership from real producer capability. Do not synthesize unavailable observations from final WAVE or TASK-048 thresholds.
4. **Implementation design:** fix the R0-compatible shared validator API, nested immutable parsed value and exact error/negative fixtures before changing code. No duplicate canonical parser, TASK-082/TASK-043/TASK-003 authority substitution, native operation or TASK-098 A5 admission.

Independent DEV-4 Critic/Tester review on this candidate found the full-envelope equality error and the unresolved matrices above. The equality rule was corrected to R0 lineage fields; the others remain explicit design blockers. Status is `DESIGN_GAP_MAP / ABI_NOT_FROZEN / IMPLEMENTATION_NOT_ALLOCATED`. Subsequent producer wiring, native validation, custody/Asset/Job binding and TASK-098 A5 each need their own authority and evidence.
