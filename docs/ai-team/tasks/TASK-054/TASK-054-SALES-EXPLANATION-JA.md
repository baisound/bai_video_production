# TASK-054 営業・お客様向け説明

## まず一言で

お手本となるDbD動画の実況・解説から、

- どの場面で話すか;
- 何を先に説明するか;
- 実況と解説をどう使い分けるか;
- どのくらい慎重に推測を伝えるか;
- どの長さ・テンポで話すか;

をAIに学ばせ、実況のない普通のプレイ動画に対して「今のAIなら、
この場面でこのような実況・解説を作ります」という完成イメージを
確認できるようにする機能です。

## お客様ができること

### 1. お手本動画から学ばせる

実況・解説が入っている動画を選ぶと、システムが音声を文字にし、
試合中の出来事と時間を合わせます。

人が、

- これは実況（起きていること）;
- これは解説（なぜ重要か）;
- これは戦術説明;
- これは反応・感情;
- これは雑談なので学ばせない;

と確認してから学習素材へ追加します。

AIが勝手に動画を正解として覚えるのではありません。聞き間違い、
話者、場面との対応、権利を人が確認した内容だけを使います。

### 2. 普通の動画で、現在の実力を確認する

`確認モード（学習しない）`で実況のない普通の動画を選ぶと、現在の
学習済みモデルが、どの時間にどんな実況・解説を作るかをTimeline上に
表示します。

このモードでは、

- 学習素材は増えません;
- AIモデルは変更されません;
- 確認結果を勝手に次の学習へ使いません.

そのため、お客様は安心して何度でも現状を試せます。

### 3. 必要な時だけ学習する

`学習モード`を選ぶと、人が修正・承認した実況・解説を新しい学習素材
として準備できます。学習を実行すると、現在使用中のAIを上書きせず、
新しいバージョンを別に作ります。

新旧を名前を伏せて比較し、本当に良くなった時だけ採用できます。
問題があれば、以前のモデルへ戻せます。

## 画面操作

通常は次の流れだけで使えます。

```text
動画を選ぶ
 -> 確認モード または 学習モードを選ぶ
 -> 自動解析
 -> 動画と同じTimeline上で実況・解説を確認
 -> 必要なら人が修正・承認
```

専門的な学習率、LoRA、GPUメモリなどは通常画面では隠し、必要な担当者
だけが `技術詳細` を開きます。長い処理には進捗、残り時間、安全な
キャンセル、再開、分かりやすい日本語エラーを用意します。

## 何が安全なのか

- AIの推測だけで「試合で何が起きたか」を確定しません;
- 公式情報やパッチ情報は学習モデルの記憶ではなく、出典付きKnowledge
  とRAGから取得します;
- 根拠が足りない場合は、無理に断定せず「判断できない」と言えます;
- 人が承認したものだけが解説候補や学習素材になります;
- お客様の秘密情報や認証キーを学習素材へ入れません;
- 公開動画だから自由に学習できるとは扱わず、権利確認を行います;
- 声そのものを真似する機能ではありません。今回学ぶのは実況・解説の
  内容、順番、タイミング、慎重さです;
- 学習、外部AI利用、費用発生、有効化は別々に確認します.

## お客様にとっての価値

- 実況者がいない動画にも、状況に合った解説案を作れる;
- 実況と解説の品質を、感覚ではなく動画上で比較できる;
- お客様独自の説明方針や情報量へ徐々に合わせられる;
- パッチが変わっても、事実はKnowledge/RAG側で更新できる;
- AIが誤った説明をした時、元の根拠と修正履歴を追える;
- 新しいモデルを試しても、現在の安定版を壊さず元へ戻せる.

## 営業が誤解させてはいけないこと

- 「動画を入れれば自動的に正しい戦術を覚える」機能ではありません;
- 「特定の実況者の声や人格をそのままコピーする」機能ではありません;
- 「AIが自動で学び続け、勝手に本番へ反映する」機能ではありません;
- 「現時点ですでに実装済み」と説明してはいけません.

現段階は、Architecture、データ形式、学習方法、操作画面、安全対策、
評価方法、復旧方法までを実装可能な粒度に落とし込んだ**詳細設計完了**
です。実装、モデル取得、実学習、外部AI実行、有効化は今後それぞれ
承認を受けて進めます。
