The staged diff contains only the four allocated TASK-068 file groups. It does not edit `atomic.py`, an existing Montage owner module, a shared registry/current-state/roadmap/CHANGELOG, release/deploy configuration, or Production data.

## Independent Critic status

## Findings addressed in the transition diff

1. **High — ancestor false positive:** exact directory metadata comparison treated an authorized file create/rename as ancestor replacement. Fixed by pinning continuity to device, inode, type, and reparse status while keeping exact file identity comparison.
2. **High — initial lock ownership:** an initial CREATE_NEW loser previously fell through to existing-lock acquisition. Fixed by explicit `initial`/`existing` one-shot capabilities; collision burns the initial capability and performs no retry.
3. **High — sensitive result representation:** a read result originally retained raw bytes in its public dataclass representation. Removed raw bytes, added byte count, and made the result representation body-free.
4. **High — durability failure residue:** a file-flush failure could leave an owned partial temp and a directory-flush failure could leave a newly published final. Fixed by exact-inode temp cleanup and exact-inode/bytes rollback of an immutable publish.
5. **High — late CAS/cleanup seam:** substitution after the first recheck could overwrite or unlink a foreign object in a testable final seam. Added a second complete inode-plus-bytes CAS binding and immediate final cleanup identity binding.
6. **Medium — lock drift:** added exact marker validation, target identity checks while held, and Windows owner/DACL material digest comparison before release.
7. **P0 — live temp/delete binding:** Windows publish and cleanup retain operation-owned live handles and use native handle-bound deletion. POSIX immutable publication now uses `O_TMPFILE` plus `linkat(AT_EMPTY_PATH)` and has no temporary-name unlink seam; POSIX exact cleanup fails closed before effect because pathname `unlinkat` cannot condition on the captured inode.
8. **P0 — mutable/unbounded JSON:** read results are deep frozen; writer depth/node/scalar/byte limits run before canonical encoding and before whole-container copies.
9. **P0 — initial-lock ambiguity:** confirmed rollback is separated from `completion_unknown`; lock initialization never treats an unverified durability failure as effect0.
10. **P0 — Windows rename corruption:** the Windows legacy `FileRenameInfo` buffer now includes an in-buffer WCHAR terminator; direct initial-lock/publish smoke no longer creates a garbage-suffixed destination.
11. **P0 — dormant unsafe code:** the unreachable pathname-based POSIX exchange/delete implementation behind the unconditional CAS rejection was removed, so unavailable authority effects cannot be revived by deleting one guard line.
12. **High — open-failure handle leak:** ancestor, target, and POSIX unnamed-temp opens now close a successfully created fd if non-inheritance verification fails before ownership transfers to the caller; POSIX tests and a Windows native smoke verify the captured handle is invalid afterward.
13. **High — cleanup-error handle leak:** immutable publish now attempts temp-handle close and pinned-parent close even when exact temp cleanup itself fails; the fault test verifies every captured descriptor is invalid after the body-free cleanup error.
14. **High — post-commit failure misclassification:** readback, ancestor revalidation, and finalization failures after namespace publication now return `PUBLISH_COMMIT_UNKNOWN` with `completion_unknown=true`; they no longer claim a confirmed pre-effect failure when the final name may remain visible.
15. **High — Windows reparse misclassification:** a junction opened with `OPEN_REPARSE_POINT` can report a non-directory mode as well as the reparse attribute. Reparse rejection now precedes type classification for both ancestors and regular targets, so the public result is consistently `REPARSE_POINT_REJECTED`.
16. **High — temp-bind cleanup ambiguity:** a Windows temp fd that failed initial identity binding could lose the original error or remain open. The failure path now performs exact handle delete plus close and returns `TEMP_CLEANUP_UNKNOWN` when either cleanup action cannot be confirmed.
17. **High — post-effect finalization ambiguity:** rollback directory durability and cleanup close/durability/ancestor failures after a namespace effect now return an explicit completion-unknown result instead of an effect0-looking error.
18. **High — untransferred ancestor fd:** `_pin_parent` now retains and closes the currently opened directory fd until validation transfers it into the pinned set. POSIX and Windows negatives prove the fd is invalid after validation failure.
19. **High — lock cleanup ambiguity:** existing- and initial-lock failure cleanup no longer suppresses target/parent close failures. The public results are `LOCK_CLEANUP_UNKNOWN` or `LOCK_INITIALIZATION_UNKNOWN` as appropriate.
20. **High — caller-controlled resource ceilings:** constructor bounds are hard ceilings (1 MiB, depth 64, nodes 100,000), exact built-in integers only, and cannot be raised or disabled by bool/float coercion.
21. **High — late initial-lock collision:** a competitor appearing at the handle-bound no-replace seam is translated to `LOCK_CREATE_COLLISION`; no retry to an existing-lock capability occurs and the competitor is preserved.
22. **Medium — path resource ceilings:** relative paths reject non-string path-like values, controls, more than 32 components, components longer than 255 characters, and total paths longer than 4096 characters before filesystem effect.
23. **High — read handle finalization:** a target-handle close failure is no longer suppressed after a successful snapshot read. The result is not returned and a body-free `HANDLE_CLOSE_FAILED` escapes after pinned-parent cleanup is attempted.
24. **High — created-name residue on open failure:** Windows `_open_target(create_new=True)` could leave an owned named temp when non-inheritance verification failed after CREATE_NEW. Open failure cleanup now deletes through the live handle, closes it, and reports `HANDLE_CLEANUP_UNKNOWN` if either operation is not confirmed.
25. **High — pin/unnamed-temp cleanup suppression:** ancestor validation and POSIX unnamed-temp setup previously suppressed close faults after an earlier rejection. Both paths now attempt all available cleanup and replace the original error with body-free `HANDLE_CLEANUP_UNKNOWN` when handle lifetime is not confirmed.
26. **High — raw Windows HANDLE gap:** failures inside `_windows_open` before CRT fd ownership transfer could bypass fd-level cleanup after CREATE_NEW. A raw-HANDLE port now applies delete disposition to the exact created object, checks `CloseHandle`, and classifies any ambiguity before returning control.
27. **Critical — final-link escape:** `_windows_rename_handle` used `Path.resolve()` after the no-destination check, so a raced final symlink could redirect a live source handle outside the pinned root. Publication now uses the already validated lexical absolute spelling without filesystem resolution; the focused race preserves the link and creates no escaped artifact.
28. **Critical — writer-root rebinding:** a POSIX attacker could move the acquired lock inode into a replacement root and make the old lease authorize an effect in that root. Lease validation now verifies its pinned ancestor, returns the acquisition-root identity, and `_bind_writer_parent` compares and revalidates the freshly pinned effect root before namespace effect.
29. **High — late hardlink deletion:** Windows handle-bound cleanup compared object fields that omitted `nlink`, allowing a hardlink added at the final injected seam to reach delete disposition. The delete path now requires exact `ArtifactIdentity` before and after the seam; the late-hardlink negative preserves both names.
30. **High — Windows reserved-namespace alias and classification TOCTOU:** raw immutable namespace rejection was case-sensitive, and the first physical-identity fix used unpinned pathname observations. Exact/case-folded variants now reject lexically. For alternate Windows components, the effect parent is pinned and writer-root-bound first, the canonical reserved parent is pinned under the same root while both handles deny rename/delete, and the candidate first-component identity—not merely its immediate nested parent—is compared before body/temp/effect. Static direct/nested 8.3 paths and both post-candidate-pin swap seams are covered.
31. **High — replayed tombstone boundary:** topology inspection alone cannot own Product monotonic/currentness semantics. `inspect_immutable_graph` now requires a consumer-owned verifier over the complete aggregate plan fingerprint plus specified coordinate; one-shot negatives reject replay and a post-tombstone resume plan while preserving every immutable artifact.
32. **High — incomplete verifier evidence:** happy-path plan verifiers now bind authorization plus the deterministic complete semantic fingerprint. POSIX and Windows parameterized negatives change path, operation, revision, body digest, predecessor, action, build, backend, session, instance, and authorization independently and prove effect zero.
33. **High boundary clarification — directory tree/mutable phase:** directory rename/snapshot commit and fixed-path journal phase advance are explicitly outside `IMMUTABLE_ONLY_V1`. Public discovery methods are `NoReturn`, expose stable non-authority status markers, and reject before path/body/hook/effect.
34. **Authority boundary — duplicate/currentness:** TASK-068 may no-replace publish and pinned-read an operation-specific immutable terminal, but cannot derive consumer `DUPLICATE` from a fixed history, last event, collision, or scan result. Publish/read/inspection receipts and errors expose `DUPLICATE_CURRENTNESS_AUTHORITY_NOT_CREATED`; POSIX and Windows negatives preserve the original terminal on repeat publication.

## Residual assessment

- Historical pre-amendment rereview closed findings 27-29 with no new regression but retained Critical/High **0/2** solely for the now-superseded mutable-CAS/delete acceptance.
- Post-restart independent architecture rereview found no implementation-only closure under the current fixed-path contract and an uncooperative namespace writer. Linux `renameat2` offers replace/no-replace/exchange but no expected-inode predicate; `unlinkat` offers pathname deletion without `AT_EMPTY_PATH` handle deletion. Exchange can detect a mismatch only after displacing the foreign target, and rollback is another raceable namespace effect. Advisory locks do not serialize an uncooperative rename/unlink. Windows non-TxF rename likewise has no expected-target-identity predicate. TxF would be NTFS-local, excludes shared/SMB cases, is discouraged for new dependencies, and would not close the cross-platform contract. Closing these two High findings therefore requires an Owner/design contract gate, not another bounded implementation patch.
- `SUPERSEDED / IMMUTABLE_ONLY_V1`: mutable CAS is not an effect-bearing v1 responsibility. Both ports expose a `NoReturn` discovery method that consumes a valid writer capability and returns `CAS_ATOMIC_UNAVAILABLE` before caller-body or filesystem access. Consumers may not treat this result as PASS or authority.
- `SUPERSEDED / IMMUTABLE_ONLY_V1`: published authority artifact deletion is not an effect-bearing v1 responsibility. Both ports expose a `NoReturn` discovery method returning `CLEANUP_ATOMIC_UNAVAILABLE` before target/hook/effect. Immutable tombstone/transition is consumer-owned; physical GC requires a separate Task/Human Gate.
- H1 correction: TASK-068 never creates/selects a current generation. Exact coordinates come only from a trusted Product plan plus monotonic durable receipt; graph enumeration is bounded integrity inspection for that specified generation, never winner selection. All receipts/statuses remain `authority_created=false`, `currentness_selected=false`, `CURRENT_HEAD_AUTHORITY_NOT_CREATED`.
- Historical independent closure review found Critical/High `0/3` for Windows reserved-namespace aliases, replayed-tombstone consumer binding, and incomplete fingerprint-verifier negatives. Findings 30-32 and their final rereviews closed all three.
- TASK-067 applicability is mode-scoped: strict pinned read may be evaluated only for `VERIFIED_READBACK/A2`. `FRESH`, `PRECOMMIT_RESUME`, and `JOURNAL_RECOVERY` need mutable manifest/journal/marker/anchor effects that remain explicitly unavailable; TASK-068 evidence or receipts must not be promoted to whole-Task or all-mode completion.
