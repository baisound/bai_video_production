## Status rules

- `IMPLEMENTED_VERIFIED`: source, relevant tests and required packaged/native
  evidence all exist.
- `IMPLEMENTED_UNVERIFIED`: implementation and source tests exist, but required
  TASK-052 Windows/Human evidence is absent.
- `PARTIAL`: only part of the contract exists.
- `STUB`: a data shape, fixture or low-depth baseline exists without the required
  Product behavior.
- `MISSING`: no conforming implementation exists.
- `SUPERSEDED_BY_CANONICAL_OWNER`: another current BVP responsibility owns the
  capability; TASK-052 must integrate rather than duplicate it.
- `INTENTIONALLY_DEFERRED`: valid design breadth explicitly outside the present
  closure.
- `CONFLICT_REQUIRES_OWNER_DECISION`: no authoritative resolution exists.

No row is `IMPLEMENTED_VERIFIED` at R0 because TASK-052 packaged Windows Evidence
has not yet been produced.
