## 2. Implementation Source of Truth and exact gap

Current main already provides:

- a `RegenerationPlan` with exact `parent_attempt_id`, current and next
  `RegenerationStrategy`, failure codes and a deterministic Plan checksum;
- a `RegenerationPromptDraft` that carries the selected Strategy while Human
  confirmation is pending;
- an immutable Prompt Registry with Prompt versions and Generation Attempts;
- a durable Generation Queue binding the exact Prompt/Profile/input/upstream
  snapshots;
- P-ORCH-1 adoption of a terminal initial-generation output through canonical
  Asset, Candidate and PASS Attempt lineage to `READY_FOR_AUDIT`.

The exact gap is between regeneration confirmation and Prompt persistence.
`RegenerationPromptDraftService.register()` persists only `PromptEntity`.
`PromptEntity` contains neither the parent Attempt nor the selected Strategy,
so both facts disappear after restart. The Queue consequently cannot persist
them, and P-ORCH-1 correctly parks every `prompt_version > 1` output as
`PARKED_STRATEGY_BINDING_REQUIRED` rather than inventing `strategy_level=0` and
`parent_attempt_id=null`.

This is `NEW_CAPABILITY_REQUIRED`, not a Native generation retry and not a
Provider integration.

## 4. Builder Design

### 4.1 One canonical regeneration lineage

Add an optional immutable `PromptRegenerationBinding` owned by TASK-040 and
stored on the new `PromptEntity` version created by the confirmed regeneration
flow. It contains only bounded metadata:

- `binding_version=1.0.0`;
- exact parent Prompt ID/version/body SHA-256;
- exact `parent_attempt_id`;
- selected `strategy_level`;
- normalized unique `reason_codes`;
- exact `regeneration_plan_sha256`.

It contains no Prompt body, credential, host path, output path or media. The
binding is the single durable Source of Truth for intended regenerated
execution lineage. Queue and adoption copy and verify it; they do not create a
second editable interpretation.

Initial Prompt version 1 has no regeneration binding and derives the exact
execution lineage `(strategy_level=0, parent_attempt_id=null)`. A newly
registered later version must use the regeneration flow. The generic Prompt
registration application must reject creation of a new version greater than 1
without this governed binding.

### 4.2 Registration invariants

At prepare and again under the existing serialized apply lock:

1. recompile the Human-authorized regeneration Plan from current Prompt,
   Production and Audit stores;
2. verify its exact checksum equals the confirmed Plan;
3. verify the parent Attempt exists, belongs to the same Prompt/Slot/version and
   has the exact parent Prompt hash;
4. verify the new Prompt is exactly the next version;
5. require Strategy to be non-decreasing from the parent Attempt;
6. allow Provider Profile change only at `PROVIDER_SWITCH` or higher;
7. construct the binding from the revalidated Plan, never from loose UI fields;
8. save Prompt plus binding atomically in the existing Prompt Registry file.

The prior Prompt version and Attempt remain immutable. A duplicate, missing,
stale or conflicting parent produces no write.

### 4.3 Prompt Registry format compatibility

The Prompt Registry writer advances its document format to `1.1.0`. The loader
accepts strict historical `1.0.0` and current `1.1.0` documents:

- v1.0 Prompt rows load without a binding;
- v1.1 accepts the exact optional binding shape and revalidates its parent graph;
- save emits only v1.1 after full domain validation and CAS;
- an historical Prompt version greater than 1 without a binding remains
  readable, but cannot receive a new Queue admission or output adoption;
- unknown versions, partial bindings, invalid Strategy, missing/cross-Slot
  parents, checksum drift or cyclic Attempt lineage fail closed.

No binding is inferred from Prompt version, most recent Attempt, Audit order or
current Strategy. This deliberately preserves truthful legacy ambiguity.

### 4.4 Queue binding and migration

New Queue entries use `entry_version=1.1.0` and persist a strict
`execution_lineage` object:

- initial: `kind=INITIAL`, `strategy_level=0`, `parent_attempt_id=null`, no Plan
  checksum;
- regenerated: `kind=REGENERATION`, exact Strategy, parent Attempt and Plan
  checksum copied from the Prompt binding.

The Queue document loader accepts its historical v1.0 entries and new v1.1
entries. Historical entries remain immutable. New admission for a later Prompt
without a valid binding is rejected with an actionable
`ERR_QUEUE_REGENERATION_BINDING_REQUIRED`. The deterministic Queue ID includes
the complete execution lineage.

`require_current_entry()` re-derives the same entry version from current
Evidence. It never silently upgrades an old entry. Existing upstream snapshot
staleness behavior remains unchanged.

### 4.5 Output adoption

P-ORCH-1 removes its version-number guess and instead requires the exact current
Queue `execution_lineage`:

- the PASS Attempt receives the Queue Strategy and parent Attempt;
- Prompt Registry domain validation again proves same Prompt/Slot lineage and
  non-regressing Strategy;
- adoption identity and transaction checksum include the lineage;
- a missing, legacy, mismatched or changed binding stays parked with no Asset,
  Candidate or Attempt side effect;
- recovery reuses only the original checksum-closed lineage and never dispatches
  or replays a Provider.

The endpoint remains `READY_FOR_AUDIT`. Human Audit, ACCEPT/LOCK, publication
and downstream generation remain separate actions.

### 4.6 Unified Shell projection

The Generation Queue workspace may show bounded read-only labels for initial or
regenerated lineage, Strategy level and logical parent Attempt ID. It must not
show Prompt bodies or suggest that queuing/adoption starts regeneration. The
existing separate Human confirmations remain mandatory.

## 5. Failure, recovery and threat model

- stale regeneration confirmation: consumed and rejected before save;
- parent Attempt missing, cross-Slot, wrong Prompt/version/hash or lower Strategy:
  fail closed;
- forged loose Queue/adoption Strategy or Parent: no API accepts it;
- v1.0 later Prompt without exact binding: readable but
  `PARKED_STRATEGY_BINDING_REQUIRED`;
- unknown/partial future Prompt or Queue format: fail closed;
- Prompt Registry checksum/CAS conflict: no write;
- Queue binding differs from current Prompt binding: entry stale, no execution or
  adoption;
- crash after Prompt save: binding is in the same atomic file as the Prompt;
- crash during Queue/adoption: existing append/CAS and adoption suffix recovery
  remain authoritative;
- secret, Prompt body, absolute host path and output bytes remain excluded from
  persisted/public projections.
